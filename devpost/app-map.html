Decision Journal: app map

A compact guide to where things live. It's a snapshot of the code at the commit below and can drift as the code changes.

What the app is.

A browser-only React app. Decisions are saved in localStorage. One file of pure functions (src/lib/stats.ts) turns the list of decisions into every number on screen, including the live Reality check that warns you while you decide.

  • Screens: src/pages/: Insights, Journal, New decision, Decision detail.
  • Data in and out: src/lib/store.tsx (state + actions) → src/lib/storage.ts (localStorage, with fallbacks).
  • The math: src/lib/stats.ts, tested in src/lib/stats.test.ts.

One action, end to end: moving the confidence slider

Reference route (3 stops)

A route to follow in your editor. Search for the anchor text in each file.

1. Input: src/pages/NewDecisionPage.tsx, search const rc = useMemo

The form keeps area, mood and confidence in React state. Every change recomputes the Reality check from the saved decisions. Nothing is saved until “Save prediction”.

2. Logic: src/lib/stats.ts, search export const realityCheck

Builds evidence rows (area, mood, confidence bucket). It needs MIN_N (3) resolved decisions before a row counts, and calls over/underconfidence only at a GAP_THRESHOLD (15 points) gap. One lead group (area + mood, then area, then mood, then confidence level) drives both the headline and the suggestion. The suggestion starts from smoothedRate = (hits + 1) / (n + 2) and stays within 10 points of what actually happened.

3. Output: src/components/RealityCheck.tsx, search function Evidence

Draws each row's meter: a hollow ring at how sure you feel now and a solid dot at how often you've been right, joined by a line colored by direction. “Use N%” calls back into the page's setConfidence.

To change this, start here

  • How strict the warnings are: MIN_N and GAP_THRESHOLD at the top of src/lib/stats.ts. Then run npm test.
  • The sample person's story: ROWS in src/lib/sampleData.ts. Tests in stats.test.ts check the Money/Career patterns still hold.
  • Areas, moods, check-back intervals: AREAS, MOODS, REVIEW_INTERVALS in src/lib/types.ts.
  • Colors and type: src/styles/tokens.css (light and dark).
  • Headline copy on Insights: summarize in stats.ts and InsightsPage.tsx.

A practice to reuse

Pin down the core idea's behavior as tests before trusting delegated code. Here, prd.md › Reality check while deciding says “Money + Excited + 90% shows an overconfidence warning that names Money.” The first version of the engine passed its general tests, but printing its real output for that exact case showed it led with the confidence bucket instead of Money. A later independent review found the headline and suggestion could disagree. The fix was locked in with an exhaustive test, “taking the suggestion always lands on ‘fits your record’”, that checks every area × mood × confidence combination in stats.test.ts. On any agent-built project: check the agent's output against the literal acceptance criterion, then turn the criterion into a test the agent has to pass before each commit.
